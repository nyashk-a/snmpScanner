# snmpScanner

**snmpScanner** — это высокопроизводительный инструмент для сбора, агрегации и персистентного хранения статистики сетевого трафика, получаемой по протоколу **SNMP (Simple Network Management Protocol)** . Решение ориентировано на мониторинг больших распределённых сетей с минимальными требованиями к инфраструктуре и без необходимости развёртывания полноценных NMS-систем.

## Архитектурная концепция

Система построена на асинхронной событийно-ориентированной модели с применением конкурентных паттернов обработки. Ядро приложения реализует следующие ключевые компоненты:

- **Асинхронный SNMP-клиент** на базе библиотеки *Lextm.SharpSnmpLib* с поддержкой **SNMPv2c** — обеспечивает неблокирующие запросы к сетевым устройствам по OID-идентификаторам, с таймаутами и автоматической обработкой исключительных ситуаций.

- **Адаптивный планировщик опроса (polling scheduler)** — распределяет множество целевых устройств по сбалансированным группам с учётом их индивидуальных таймаутов (алгоритм *least-loaded balancing*), минимизируя задержки и предотвращая перегрузки как на стороне сканера, так и на опрашиваемых агентах.

- **Двухуровневое хранилище временны́х рядов**:
  - *Минутный кэш* — буферизация инкрементальных счётчиков трафика в оперативной памяти с последующей записью в бинарный журнал.
  - *Суточный агрегатор* — свёртка минутных данных в дневные отчёты с автоматической детекцией дублирования и атомарной заменой файлов.

- **Персистентное NoSQL-хранилище** на основе **MessagePack** (бинарный формат сериализации, превосходящий JSON по компактности и скорости) с механизмом атомарной замены файлов (*atomic file replacement*) и фоновой периодической синхронизацией (*auto-save*), гарантирующей целостность данных даже при аварийном завершении работы.

## Ключевые преимущества

### 1. Масштабируемость и производительность
- **Пакетный параллелизм** — опрос устройств выполняется конкурентно в пределах сбалансированных групп, что позволяет эффективно утилизировать ресурсы многоядерных систем.
- **Регулируемая степень параллелизма** — количество одновременно опрашиваемых групп настраивается автоматически в зависимости от числа устройств (по умолчанию до 40 групп), с динамической задержкой старта для предотвращения *thundering herd* эффекта.
- **Асинхронный ввод-вывод** — все операции с сетью и диском реализованы на основе `async/await`, исключая блокировки потоков.

### 2. Отказоустойчивость и надёжность
- **Гранулярная обработка ошибок** — сбои при опросе отдельных устройств или интерфейсов логируются, но не прерывают общий цикл мониторинга.
- **Атомарные операции записи** — сохранение данных происходит через временный файл с последующей заменой, исключая коррупцию хранилища при сбоях питания или ОС.
- **Автоматическое восстановление** — при старте система загружает последнее консистентное состояние из бинарного хранилища.

### 3. Экономичность и автономность
- **Отсутствие внешних зависимостей** — не требует СУБД, веб-серверов или дополнительных сервисов. Всё работает из одного каталога.
- **Минимальный сетевой трафик** — опрос выполняется по протоколу UDP с компактными SNMP-запросами, что критично для каналов с ограниченной пропускной способностью.
- **Низкое потребление ресурсов** — бинарная сериализация MessagePack и отсутствие избыточных парсеров обеспечивают малый footprint по памяти и диску.

### 4. Гибкость эксплуатации
- **Конфигурирование через CSV** — список целевых устройств загружается из простого текстового файла, что упрощает интеграцию с существующими системами инвентаризации.
- **Автоматическое обнаружение интерфейсов** — сканер самостоятельно определяет открытые (активные) интерфейсы на каждом устройстве, опрашивая OID `ifInOctets` в диапазоне до 60 портов.
- **Логирование с ротацией** — все события и ошибки сохраняются в текстовый журнал с временны́ми метками для последующего аудита и отладки.

## Области применения

- Мониторинг пропускной способности каналов в корпоративных сетях.
- Сбор статистики для биллинговых систем и анализа загрузки.
- Обнаружение аномалий трафика и нештатных ситуаций.
- Лёгкая альтернатива тяжеловесным NMS-решениям (Zabbix, PRTG, Cacti) для средних и малых инсталляций.

| Компонент | Технология |

## Быстрый старт

1. Поместите список IP-адресов устройств в файл `source.csv` (по одному адресу на строку) в каталоге с исполняемым файлом.
2. Запустите приложение с параметрами командной строки:
   - `--check-new` — выполнить первичное обнаружение интерфейсов.
   - `--monitoring` — запустить непрерывный цикл сбора статистики.
   - `--no-log` — отключить ведение журнала (для повышения производительности).
3. Статистика будет сохранена в файлы `addressDB.bin`, `todaystatDB.bin`, `globalstatDB.bin`.
